# Domain docs

Before exploring a domain, read `GLOSSARY.md` at the repository root. If `GLOSSARY-MAP.md` exists, follow it to the glossaries relevant to the task. Read related decisions in `docs/adr/` and, for multiple contexts, `src/<context>/docs/adr/`.

Proceed when these documents do not exist. Create terminology and decisions lazily as they are resolved. Use glossary terms in code discussions, tickets and proposals; surface conflicts with an existing ADR before changing its decision.

The initial layout is single-context: root `GLOSSARY.md` and `docs/adr/`. The scaffold provides these consumer rules without inventing domain terms or decisions.
