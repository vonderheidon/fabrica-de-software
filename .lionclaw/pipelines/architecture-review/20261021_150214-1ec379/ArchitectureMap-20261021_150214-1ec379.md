# Architecture Map: Nova fábrica de software
**Data:** 2026-10-21
**Run:** 20261021_150214-1ec379

## Resumo do sistema
Fábrica local que transforma issues GitHub em tentativas de implementação, checks, revisão independente e entrega, coordenando Maestri/OMP e conteúdo Git. A UI React conversa por HTTP/JSON e SSE com um controlador Node.js/Fastify; SQLite guarda estado operacional e referências, enquanto Git mantém o conteúdo das versões de entrega.

Stack observada: TypeScript strict, Node.js 24, Fastify 5.12.7, React 18.3.1, Vite 8.3.4 e better-sqlite3 13.0.3. package.json configura build com TypeScript/Vite e cópia de recursos; Vitest 5.0.5 cobre testes locais, com configurações separadas para provas HTTP/nativas e scripts de smoke/distribuição. scripts/check-boundaries.mjs restringe imports e posse de SQL/subprocessos. Não há processo Electron/preload identificado: o transporte web é HTTP/SSE; o Adapter de execução possui canal próprio para Maestri/OMP.

Cada agrupamento abaixo é um Module com Interface e Implementation; agrupamentos internos explícitos ajudam a mostrar os fluxos sem afirmar independência de pacote. As dependências nomeiam IDs deste mapa ou ferramentas externas. O campo risk indica prioridade qualitativa de investigação.

## Modules top-level
### Interface web
- **Path:** apps/web/src
- **Role:** Renderiza navegação por hash, diálogos e jornadas de projetos, configuração, fila e tentativas. Entry point main.tsx monta AppShell.
- **Dependencias:** web-transport; contracts.
- **Chamadores:** Operador no navegador.
- **Classificação:** layer=frontend; kind=ui; risk=medium.

### Transporte e observação web
- **Path:** apps/web/src/api
- **Role:** Interface requestJson/requestText mantém sessão e CSRF; preserva ETag e traduz erros. O Module de observação em app/controller-events.ts consome SSE e solicita ressincronização.
- **Dependencias:** http; contracts.
- **Chamadores:** web.
- **Classificação:** layer=frontend; kind=adapter; risk=medium.

### Composição do host
- **Path:** scripts/start-host.mjs
- **Role:** Compõe caminhos nativos e contexto herdado; chama startController. main.ts adquire lock, abre storage, valida execução e conecta os Modules antes de listen em loopback.
- **Dependencias:** http; storage; github; workspaces; execution; pipeline; verification; projects; deletion.
- **Chamadores:** npm start.
- **Classificação:** layer=main; kind=adapter; risk=high.

### Interface HTTP local
- **Path:** apps/controller/src/http
- **Role:** createApp instala segurança, sessão, contratos, arquivos web e rotas versionadas; converte DTOs públicos e delega comandos e consultas. Expõe eventos paginados e SSE.
- **Dependencias:** contracts; projects; pipeline; storage; queries; diagnostics; deletion.
- **Chamadores:** web-transport; host.
- **Classificação:** layer=main; kind=adapter; risk=high.

### Projetos e configuração
- **Path:** apps/controller/src/modules/projects
- **Role:** createProjects governa cadastro, configuração global/por projeto, perfis, seleções nativas e opções. O mesmo pacote contém preparação, observação da fila e scaffold, descritos como Modules próprios abaixo.
- **Dependencias:** contracts; storage; github; workspaces; execution; queue.
- **Chamadores:** http; host.
- **Classificação:** layer=main; kind=service; risk=high.

### Preparações
- **Path:** apps/controller/src/modules/projects/preparations.ts
- **Role:** Interface createPreparations é composta com storage, github e workspaces; oferece criação, leitura e revalidação do resumo usado por startAttempt. O corpo interno não foi aprofundado.
- **Dependencias:** storage; github; workspaces.
- **Chamadores:** http; pipeline; host.
- **Classificação:** layer=main; kind=service; risk=medium.

### Fila Ready
- **Path:** apps/controller/src/modules/projects/queue.ts
- **Role:** Observa identidade, Projects e issues; produz elegibilidade, ordenação e backoff. read mantém observação para exibição; save e scheduler exigem observação atual. Não despacha sozinho.
- **Dependencias:** contracts; storage; github.
- **Chamadores:** projects; pipeline; host.
- **Classificação:** layer=main; kind=service; risk=high.

### Criação de projetos
- **Path:** apps/controller/src/modules/projects/scaffold.ts
- **Role:** Planeja criação com template/digest, destino e modalidade; coordena trabalho assíncrono, efeitos duráveis e reconciliação. Consulta recursos distribuídos de engenharia.
- **Dependencias:** contracts; storage; github; workspaces; resources/templates.
- **Chamadores:** http.
- **Classificação:** layer=main; kind=service; risk=high.

### Coordenação das tentativas
- **Path:** apps/controller/src/modules/pipeline
- **Role:** createPipeline coordena início, polling, revalidação de escopo, captura, checks, revisão, correção, perguntas e encerramento. Composição inclui recuperação e publicação; callbacks de resultados promovem o fluxo.
- **Dependencias:** contracts; storage; preparations; queue; execution; workspaces; verification; publication; github.
- **Chamadores:** http; host; storage.onResultAccepted; timer interno.
- **Classificação:** layer=main; kind=engine; risk=high.

### Execução Maestri/OMP

- **Role:** Interface Execution oferece preflight, catálogo, início/continuação de passagem, perguntas, cancelamento e interação. Adapter Maestri/OMP combina contexto nativo, canal, bootstrap e persistência injetada; resultados estruturados são validados.
- **Dependencias:** contracts; ExecutionPersistence fornecida por storage; Maestri; OMP; resources/roles.
- **Chamadores:** pipeline; host; projects; diagnostics.
- **Classificação:** layer=external; kind=adapter; risk=high.

### Conteúdo e ambientes Git

- **Dependencias:** contracts; github; Git; filesystem; recursos nativos Windows.
- **Chamadores:** host; projects; preparations; scaffold; pipeline; verification; publication; deletion.

### Verificações e evidências
- **Path:** apps/controller/src/modules/verification
- **Role:** Materializa a versão para checks, confere diretórios, executa checks e registra conclusões. Carrega artefatos sob demanda com conferência de integridade e escopo.
- **Dependencias:** storage; workspaces; filesystem; executor de checks.
- **Chamadores:** pipeline; publication; host.
- **Classificação:** layer=main; kind=service; risk=high.

### Publicação e autoridade
- **Path:** apps/controller/src/modules/publication
- **Role:** Revalida conta, issue, responsável e posição no Kanban; coordena efeitos conforme modo ICR, commit ou PR. Registra intenções e confirmações, reconcilia efeitos incertos e aceita aumento explícito de modo.
- **Dependencias:** contracts; storage; github; workspaces; verification.
- **Chamadores:** pipeline.
- **Classificação:** layer=main; kind=service; risk=high.

### Persistência SQLite
- **Path:** apps/controller/src/modules/storage
- **Role:** Interface Storage reúne configuração, tentativas, passagens, entregas, checks, revisão, perguntas, efeitos, fila, exclusão e consultas. openStorage usa better-sqlite3, migrations e operações transacionais; fornece ExecutionPersistence e notificações de resultado.
- **Dependencias:** contracts; better-sqlite3; migrations SQL; filesystem.
- **Chamadores:** host; http; projects; preparations; queue; scaffold; pipeline; verification; publication; diagnostics; deletion; queries.
- **Classificação:** layer=data; kind=store; risk=high.

### Integração GitHub

### Exclusão de projetos

- **Dependencias:** storage.deletionWorker; workspaces.

### Consultas de operação e histórico
- **Path:** apps/controller/src/modules/queries
- **Role:** Interface createQueries projeta chamadas de lista/detalhe de tentativas, entregas e operação diretamente para Storage. A Implementation lida com delegação; a consistência dos snapshots pertence a storage.

- **Classificação:** layer=main; kind=service; risk=low.

### Diagnóstico contextual
- **Path:** apps/controller/src/modules/diagnostics
- **Role:** Coordena observações explícitas de configuração, identidade, contexto Maestri e registros de recursos; persiste intenção e resultado e limita trabalho pendente.
- **Dependencias:** contracts; storage; github; projects; execution.
- **Chamadores:** http.

- **Chamadores:** web; web-transport; http e Modules do controlador.
- **Classificação:** layer=shared; kind=util; risk=medium.

## Fluxos principais
### Inicialização local
1. npm start executa scripts/start-host.mjs, que compõe contexto Windows e quatro caminhos EXE: Git, Maestri, OMP e PowerShell.
2. startController resolve configuração, adquire lock e abre storage; compõe github, workspaces e execution.
3. Preflight de execution e validação dos recursos precedem createPipeline/createApp; o coordenador de exclusão recupera trabalhos registrados.
4. O controlador escuta no endereço configurado, com porta padrão de produto 4310; fechamento revoga coordenação e libera persistência/lock.

### Preparação até entrega revisada
1. A web envia comandos pela Interface HTTP, com sessão, CSRF e revisão esperada; a preparação fornece resumo para autorização.
2. pipeline.startAttempt recupera operação idempotente, revalida configuração, autoridade, perfis e resumo; storage.createAttempt confirma captura/intenção antes do despacho.
3. workspaces.prepareAttempt cria ambiente próprio e execution.startPassage inicia Implementador com perfil e critérios capturados.
4. Resultado aceito por ExecutionPersistence aciona storage.onResultAccepted; pipeline captura conteúdo Git e chama verification.verifyDelivery.
5. pipeline materializa revisão independente e inicia Revisor; rejeição pode abrir correção na sessão de implementação e nova versão, dentro dos limites.
6. Aprovação aciona publication.publishApproved; os efeitos seguem o modo autorizado.

### Despacho automático da fila
1. Timer do pipeline chama tick, observa limites, autoridade e escopo e consulta queue.observe respeitando polling/backoff.
2. Observações válidas alimentam os ciclos duráveis em storage; nova consulta seleciona candidato elegível quando a automação está ligada.
3. O scheduler cria preparação e usa o mesmo startAttempt do início manual, incluindo identidade do ciclo para consumo atômico.

### Publicação e reconciliação
1. publication revalida autoridade atual e versão/evidências aprovadas.
2. storage guarda intenção e claim dos efeitos; workspaces executa commit/push quando pertinentes e github executa efeitos remotos conforme modo.
3. Recibos confirmados permitem avançar; efeitos running/unknown são reconciliados por observação antes de continuidade.
4. Conclusão local e projeção de estado no Kanban permanecem fatos separados.

### Observação da operação pela web
1. main.tsx monta AppShell; jornadas consultam JSON e preservam metadados de revisão via transporte web.
2. Rotas delegam resumos/detalhes para queries ou Storage e projetam DTOs públicos.
3. O observador web obtém event_cursor e abre /api/v1/events/stream; valida frames e deduplica sequência.
4. Eventos e resync solicitam atualização de leituras; recuperação da sessão não repete automaticamente mutações.

### Criação de projeto
1. scaffold.plan valida escolhas, catálogo/digest, destino, conta e modalidade e produz plano.
2. A criação aceita intenção durável e agenda trabalho com workspaces e, nas modalidades remotas, github.
3. Etapas e efeitos são registrados; reconciliação consulta efeitos incertos antes de registrar conclusão.

### Exclusão durável de projeto
1. A Interface HTTP encaminha o pedido ao Module de exclusão e à persistência correspondente.
2. createDeletionCoordinator reivindica trabalho e reconfere inventário, bloqueios e identidade dos alvos por workspaces.
3. Remoções registram progresso; nova conferência exige ausência antes da finalização SQL.
4. Falha preserva progresso e estado pendente/reconfirmação; recuperação na inicialização não equivale a restaurar sessões de agentes.

## Hotspots de complexidade
- **Coordenação e continuidade das tentativas:** Timer, callbacks de resultados, tarefas pendentes, cancelamento, revisão/correção e autoridade cruzam persistência e IO assíncrono. Ordenação e estados de falha fazem parte da Interface e merecem triagem conjunta. Paths: `apps/controller/src/modules/pipeline/start.ts`, `apps/controller/src/modules/pipeline/recovery.ts`, `apps/controller/src/modules/publication/index.ts`. Próxima fase: target-triage.
- **Interface transacional e projeções persistidas:** Storage reúne muitas famílias de estado, recibos, idempotência, revisões e notificações. A correção depende das relações e transações por trás da Interface; não foi feita auditoria de todos os SQLs. Paths: `apps/controller/src/modules/storage/index.ts`, `apps/controller/src/modules/storage/migrations`, `apps/controller/src/modules/storage/execution.ts`, `apps/controller/src/modules/storage/effects.ts`. Próxima fase: target-triage.
- **Lifecycle Maestri/OMP e resultados oficiais:** Passagens vivas, bootstrap, canal, handshake de perfil, resultado validado, resposta humana e parada incerta interagem com registros duráveis. A separação entre coordenação revogada e parada comprovada exige aprofundamento. Paths: `apps/controller/src/modules/execution/adapters/maestri-omp`, `apps/controller/src/modules/execution/index.ts`. Próxima fase: target-triage.
- **Exclusão com identidade de alvos e progresso durável:** Inventário, geração do worker, reconferência anterior a cada remoção, caminhos Windows e finalização SQL participam de um mesmo fluxo. O mapa observou o coordenador e a composição, sem comprovar as garantias nativas. Paths: `apps/controller/src/modules/projects/deletion.ts`, `apps/controller/src/modules/storage/project-deletion-worker.ts`, `apps/controller/src/modules/storage/project-deletions.ts`, `apps/controller/src/modules/workspaces/deletion.ts`, `resources/deletion/windows-reference.cs`. Próxima fase: target-triage.

## O que nao foi mapeado
- Mapeamento estático top-level, sem execução de testes, build, navegador, providers, Maestri/OMP, GitHub ou operações Git com efeitos. Não constitui aceite AC/INT.
- Fontes: README.md, SPEC.md e INTEGRACAO-MAESTRI-OMP.md foram consultados em trechos; GLOSSARY.md, package.json, composição e Interfaces centrais foram lidos. Saídas extensas tiveram cortes; não houve leitura integral de toda a documentação.
- Arquivos versionados foram lidos por git show HEAD e comparados com git diff HEAD nas árvores analisadas, sem diferenças. CodeGraph forneceu trechos atuais de main.ts, AppShell.tsx e controller-events.ts. git status mostrou .lionclaw/ e discovery-notes.md não versionados; seu conteúdo não foi usado.
- Não foram encontrados ADRs ou CONTEXT entre os caminhos versionados listados; documentos não versionados/ignorados não foram inventariados integralmente.
- O README descreve launcher com cinco caminhos EXE; scripts/start-host.mjs lido exige quatro e descobre GH posteriormente. O fluxo do mapa segue a Implementation; a divergência documental não foi resolvida.
- prepare/recovery/capture/publication internos de workspaces, SQLs individuais, implementações nativas Windows, extensão/canal Wire e todas as jornadas web não foram auditados por inteiro. Dependências desses agrupamentos representam composição/imports e usos visíveis, não um grafo exaustivo de chamadas.
- resources/roles e resources/templates foram identificados pelos chamadores, sem auditoria integral de seus conteúdos; docs/, ensaios-fabrica/ e testes foram reconhecidos como suporte e evidências, sem serem tratados como Implementation de produção.
- risk é indicação qualitativa de complexidade para triagem; não representa vulnerabilidade confirmada. Layer e kind são classificações do mapa; kind=service é apenas o valor exigido pelo schema.
- Depth, Leverage, Locality e deletion test não foram medidos. A Interface é a superfície de teste; a cobertura real de seus tipos, invariantes, modos de erro, ordenação e configuração permanece para aprofundamento.
